03Executive summary

stardust.style is a fast, accessible, sharply voiced four-page site whose weakest surface is the one its business depends on: conversion focus scores 50 against the heaviest weight in the rubric (20) — one install CTA on the whole home page, four install commands with zero copy-to-clipboard affordances, and 27 distinct labels scattered across 59 CTA instances. Five P1 defects head the ledger: trailing-slash URL variants that hard-404 with no redirect; structured data injected client-side only, invisible to the AI crawlers the product itself courts; the core teaching example truncated mid-word on the conversion page; a letter-split animation that drops space glyphs, rendering “Getstarted” in the primary docs nav; and the missing closing CTA at the moment a convinced reader would install. Performance is the standout at 92 — every Core Web Vitals cell measures good, with zero layout shift and zero long tasks. The scores assume the plugin install is the primary conversion action and read the site in the brand (marketing) register, with /docs/* as conversion-support pages. Core Web Vitals are unthrottled local lab measurements; with LCP between 200 and 316 ms the good classification holds even under a 4× throttle margin.

Stated assumptions (audit.json#assumptions)

  1. Primary conversion action assumed to be the plugin install (hero CTA “Install in two minutes” → /docs/ install commands); the GitHub repo is treated as the secondary ask.
  2. The site is read in register “brand” (marketing/landing) with /docs/* as conversion-support pages.
  3. Core Web Vitals are unthrottled local lab measurements (PSI API rate-limited without a key); with LCP 200–316 ms the good classification holds even under 4× throttle margin, so the dimension is scored rather than nulled.
  4. The sub-5% amber pixel share is scored as a deliberate restraint strategy on a dark-canvas brand whose ink/cream grounds are themselves brand colors — not as template default (the palette is fully tokenized and distinctive).
  5. The first crawl pass dropped animated h1s (crawler defect, fixed and re-crawled); all heading data below is from the corrected live-DOM capture.

05Findings ledger

22 findings — 5 P1, 8 P2, 9 P3.

Priority 1

5 findings — defects that cost visitors or falsify the brand promise
F-001
P1Technical SEO

Trailing-slash variants 404 with no redirect

Observed

/docs, /docs/commands, /aem/ all return 404 while their canonical twins return 200; no 301 in either direction; the sitemap convention is itself mixed (/aem bare, docs pages slashed).

Impact

External links, shares, and typed URLs on the wrong slash form hard-404 — lost visitors and discarded link equity on a 4-page site where every backlink matters.

Fix

Add 301s from each non-canonical variant at the edge; better, adopt one convention site-wide and update canonicals + sitemap + internal links in one change.

F-002
P1Content & LLM visibility

Structured data is injected client-side only — invisible to AI crawlers

Observed

Static HTML carries 0 ld+json blocks; the rendered DOM has a full @graph (Organization + WebSite + SoftwareApplication with license and free Offer) on every page — GPTBot, ClaudeBot, PerplexityBot and Bing’s non-rendered pass never see it.

Impact

A product whose positioning is “the AI-facing web” is entity-invisible to the exact crawlers it courts; competing tools with static SoftwareApplication markup win the entity slot.

Fix

Emit the identical JSON-LD @graph in the served HTML head (head.html or publish-time metadata) instead of scripts.js; add TechArticle with dateModified on the three non-home pages.

F-003
P1Conversion focus

Key teaching example truncated mid-word on desktop docs

Observed

pre.code clientWidth 538px vs scrollWidth 768px, no scrollbar, fade, or wrap — while ~390px of margin sits unused beside it.

Impact

The one sentence that teaches the product’s core interaction (directing a redesign in natural language) is silently amputated on the conversion page.

Fix

white-space: pre-wrap on long command examples (or widen the pre), plus a copy button.

F-004
P1Brand expression

Letter-split animation drops space glyphs — “Getstarted” in the primary docs nav, “Redesignthe Web.” in the home h1 textContent

Observed

/docs/ active sidebar renders “Getstarted”; the home h1 textContent is “Redesignthe Web.” and its anchor id redesignthe-web — systemic to the per-character span animation.

Impact

A typo in the primary nav of a design tool selling craft discipline falsifies the brand promise in seconds — and the h1 the crawlers index reads “Redesignthe”.

Fix

Preserve space characters in the letter-split (nbsp or white-space: pre on space spans); slugify with the visual break as a word separator.

F-005
P1Conversion focus

No closing CTA and no copy affordance at the conversion moment

Observed

Exactly 1 “Install in two minutes” link on the whole home page (hero only); the page ends on the AEM upsell then footer; the /docs/ install block is 4 commands across 2 marketplaces with 0 copy-to-clipboard affordances site-wide.

Impact

Peak-end violation: a convinced scroller must scroll back to the hero to convert, and the “two minutes” promise is spent hand-transcribing four commands.

Fix

Repeat the install CTA after the last home section; add copy buttons to every pre; close the install block with a confirmation beat.

Priority 2

8 findings — meaningful drag on conversion, retrieval, or brand
F-006
P2Content & LLM visibility

“Free” is never stated in crawlable text on any page

Observed

grep across all four live pages: “free” matches only “freeform”; Apache 2.0 appears on the home page and llms.txt only.

Impact

“Is Stardust free / what does it cost” yields no extractable answer passage anywhere — the answer engines must infer, and inference goes to competitors or hallucination.

Fix

One explicit sentence on home + /docs/ install: “Stardust is free and open source under the Apache 2.0 license — there is no paid tier.”

F-007
P2Content & LLM visibility

All 8 llms.txt command deep-links use anchors that do not exist

Observed

llms.txt links #uplift, #extract, …; the live h2 ids are #stardustuplift, #stardustextract, #stardustdeploy--ship-to-aem, …

Impact

Agents following llms.txt land at the top of a 22KB page instead of the passage — degraded retrieval and citation precision for every command query.

Fix

Rewrite the eight anchors to the real ids, or give the h2s stable short ids.

F-008
P2Brand expression

The site mocks AI design grammar while writing in it

Observed

26–54 uppercase tracked eyebrows per page; three near-identical eyebrow + h3 + muted-body card trios on home; /aem repeats the same grammar twice; the copy itself says “Lists the moves an LLM reaches for first… Stardust subverts them deliberately”.

Impact

Undercuts the anti-average positioning for exactly the audience (designers, AEM partners) that recognizes the scaffold.

Fix

Keep the mono kicker as one named, sparing system; restructure at least one card band per page into a different affordance; vary the /aem hero from the home hero.

F-009
P2Accessibility

“Copy link” aria-labels promise an action that never happens

Observed

All 8 permalink anchors on /docs/commands/ carry aria-label="Copy link to stardust:<cmd>" but scripts contain zero clipboard/writeText calls.

Impact

Screen-reader users “copy” repeatedly and get nothing — an accessible-name lie on the page developers share links from.

Fix

Implement copy-to-clipboard with a confirmation state, or relabel to “Link to section”.

F-010
P2Visual hierarchy & craft

Mobile: hex-seed mark collides with the hero eyebrow; long commands hide up to 2× viewport width

Observed

Hex seed “a3f7” overlaps the STARDUST eyebrow glyph-on-glyph; /docs/commands/ code blocks measure scrollWidth/clientWidth up to 693/350 with no scrollbar or fade; the commands page is ~14,000px tall with no TOC access after the top.

Impact

The brand’s first mobile impression is a rendering collision, and half of every long command is invisible to a mobile reader.

Fix

Hide the decorative hex marks below ~480px; wrap or fade long commands; add a persistent jump-to-command affordance on mobile.

F-011
P2Conversion focus

One proof asset for the whole site — the “three variants” differentiator is never shown

Observed

The same coffee-site before/after pair is the only imagery on the site (2 imgs home, 2 on /aem, 0 on docs); the copy claims “three variant theses per page, each rendered, each rationalized” but no variant trio is ever pictured.

Impact

The core differentiator remains an unillustrated claim at the exact moment the visitor evaluates proof.

Fix

Add a variant A/B/C strip for one page of the sample redesign; point the before/after images at the live sample.

F-012
P2Conversion focus

Insider vocabulary gates the pitch before any concrete image

Observed

Hero paragraph leads with “a brand expression for today only — one that this brand and this date alone can produce”; “seed”, “canon”, “register” recur undefined; “do I need Claude Code?” answered only implicitly four sections into /docs/ (see Fig. 1, hero).

Impact

First-time visitors must decode the philosophy before learning what the tool does or requires — abandonment risk at the fold.

Fix

One concrete sentence at the fold (“Point it at your URL; get a redesigned, deployable copy of your site”) and a visible “Requires Claude Code” chip next to the install CTA.

F-013
P2Content & LLM visibility

Home and /aem headings are slogan-heavy (8/15 and 6/10 slogans)

Observed

“Every design tool promises uniqueness.”, “The seed picks the lane.”, “Web publishing changed under us.” carry no askable topic; /docs/ is 7/7 topic-bearing.

Impact

Slogan headings block passage retrieval for “how does Stardust work” / “why AEM Edge Delivery” queries even though the prose beneath answers them.

Fix

Keep the slogans as styled eyebrows; let the h2 carry the topic (“How Stardust works: extract → direct → prototype → migrate”).

Priority 3

9 findings — polish, consistency, and durability
F-014
P3Accessibility

Footer sigil fails AA at 3.48:1 — the only genuine contrast failure

Observed

rgba(245,240,230,0.4) 10px text over #0a1024 = 3.48:1 (needs 4.5:1); every other live pair passes — amber on ink 10.37:1, amber-deep on cream 5.91:1, muted body 4.80:1.

Impact

One decorative line unreadable for low-vision users on an otherwise exemplary a11y surface.

Fix

Raise the sigil to dust-55+ (dust-50 already measures 4.80:1) or enlarge it.

F-015
P3Visual hierarchy & craft

Vertical rhythm collapses at the largest type; the scale is ad-hoc

Observed

Two of five 77.6px h2s on home have 0px margin to the following paragraph vs 56–64px on siblings; 10 heading sizes with step ratios 1.14–1.45 and no consistent ratio; 9 distinct radii.

Impact

A typography-led brand selling typographic discipline shows inconsistent rhythm at its most visible sizes.

Fix

Consistent margin-block-end on display h2s; adopt a named modular scale and a 2–3 value radius vocabulary in the token layer.

F-016
P3Technical SEO

og:type missing on all 4 pages; docs pages share a generic og:image

Observed

og:title/description/image/url + twitter:card present everywhere; og:type null everywhere; /docs/ and /docs/commands/ fall back to default-meta-image.png.

Impact

Spec-incomplete OG markup and a generic share image weaken share CTR for documentation links.

Fix

Add og:type=website via head.html; page-specific og:images for the docs pages.

F-017
P3Technical SEO

/docs/commands/: the prepare-migration section is missing its h2

Observed

After /stardust:migrate (h2), a second Syntax/Flags/Writes/Example h3 group appears with no owning h2 before /stardust:deploy; the meta description promises prepare-migration coverage.

Impact

The command is not addressable in the document outline — it cannot rank for its own queries and screen-reader users cannot navigate to it.

Fix

Add the missing /stardust:prepare-migration h2 matching the other seven command sections.

F-018
P3Content & LLM visibility

License and authorship facts live only on the home page

Observed

“Apache” per page: / = 2, /aem = 0, /docs/ = 0, /docs/commands/ = 0; “Adobe” absent from /docs/commands/ entirely.

Impact

Docs pages are the most likely retrieval targets for install queries but carry zero trust/provenance facts.

Fix

Add the home-footer fact line to the shared footer of every page.

F-019
P3Content & LLM visibility

Performance claims are unsourced and pages carry no freshness signals

Observed

“100/100 Lighthouse scores… the default” and “top-decile Core Web Vitals” carry no linked source or date; no page shows a last-updated line.

Impact

Unsourced superlatives are discounted by answer engines; undated docs lose retrieval weight.

Fix

Link the CWV claims to aem.live performance documentation; add a visible last-updated line + dateModified schema on docs pages.

F-020
P3Brand expression

Palette pairings are one-way streets and the logo has one variant

Observed

4 of 8 palette entries used in a single context only; #854f17 passes contrast only on cream, #e8b95e only on ink; one amber-on-transparent logo variant captured.

Impact

Any new surface that recombines the tokens naively ships illegible amber-on-cream or an invisible logo.

Fix

Document allowed color pairings as token aliases; ship a logo variant set (mono, inverted, on-cream).

F-021
P3Conversion focus

CTA vocabulary fragments: 7 labels for GitHub, 4 for the install destination

Observed

27 distinct labels over 59 CTA instances; the gold DOCS nav pill reads as CTA on home and as accidental active state on docs; /aem is reachable only from the last home section.

Impact

Scattered labels dilute the scent trail to the two destinations that matter and blur wayfinding.

Fix

Canonicalize one label per destination; distinct active state for the nav pill; add /aem to the nav or footer.

F-022
P3Brand expression

The single accent is under-spent: amber paints 0.99% of the home page

Observed

Amber family 0.99% of 138,600 sampled pixels; between the seed section and the AEM band chroma appears only in italics and 11px eyebrows (see Fig. 2).

Impact

The long tell-don’t-show mid-page reads monochrome and abstract exactly where attention flags.

Fix

Spend the accent on one committed mid-page moment (an amber band, a large annotated artifact, or the variant-trio strip).

08Benchmarks

Three references from the same vertical.

Dark developer-tool / AI-product marketing sites, retrieved via the refero style index during the audit’s benchmark pass.

Langbase

langbase.com

Two-level text-color discipline (Canvas White #fafafa + Ash Gray #a1a1aa only) — stardust.style runs a 5-step dust alpha ramp (72/50/30/15/8%) that dilutes hierarchy; Langbase also frames sections with faint structural grid lines instead of relying on spacing alone.

Eraser

tryeraser.com

Role-based type scale (caption / body / subheading / heading / heading-lg / display — 6 sizes) and a strict radius vocabulary (16px cards / 8px elements / 4px buttons) — stardust.style’s scale is ad-hoc across 10 sizes with no consistent ratio; Eraser also owns a distinctive display face (National 2 Condensed) where stardust rides the SF Pro system stack.

Metaview

metaview.ai

Single-vivid-accent discipline (Mint Glare #7affb4 reserved exclusively for primary CTAs) — stardust.style splits its amber identity across three values (#e8b95e / #ffd98a / #854f17) with text-only/background-only role imbalance, so no one amber is unambiguously “the action color”.

Shared pattern: all three pair the dark canvas with an ownable display face and a tight token vocabulary. stardust.style’s distinctive assets — the cream-on-ink inversion sections, the mono eyebrow labels, and the star glyph — are underused as a system, per the findings above.
